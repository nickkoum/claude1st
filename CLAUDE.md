## Git Conventions

### Branch naming

- Feature branches: `feature/<short-description>`
- Bug fixes: `fix/<short-description>`
- Claude Code task branches: `claude/<task-id>` (auto-generated by Claude Code web)
- Releases: `release/<version>`

### Commit messages

Follow the [Conventional Commits](https://www.conventionalcommits.org/) format:

```
<type>(<scope>): <short summary>

[optional body]
```

Common types: `feat`, `fix`, `docs`, `refactor`, `test`, `chore`

Examples:
- `feat(auth): add JWT login endpoint`
- `fix(api): handle null response from upstream`
- `docs: add CLAUDE.md with project conventions`

### Pull requests

- Keep PRs focused — one concern per PR.
- Include a clear description of *why* the change is needed, not just *what* changed.
- All CI checks must pass before merging.

## Development Workflow

Since no tech stack has been committed yet, this section will be updated once the project language/framework is chosen. General rules until then:

1. **Read before editing** — Always read relevant files before modifying them.
2. **No speculative changes** — Only make changes that are directly requested or clearly necessary.
3. **No unnecessary files** — Do not create documentation files, boilerplate, or scaffolding that wasn't asked for.
4. **Keep it simple** — Prefer the minimum complexity that satisfies the requirement.
5. **Security first** — Never introduce SQL injection, XSS, command injection, or other OWASP Top 10 vulnerabilities.

## AI Assistant Instructions

### What to do

- Follow the branch and commit conventions above.
- When asked to implement something, read existing code first to understand context.
- Push finished work to the designated branch specified in the task.
- Use `git push -u origin <branch>` when pushing for the first time.

### What NOT to do

- Do not push to `main` or `master` without explicit user permission.
- Do not amend published commits — create new ones instead.
- Do not skip git hooks (`--no-verify`) unless the user explicitly requests it.
- Do not add unrequested features, refactors, or "improvements."
- Do not leave TODOs in committed code without a corresponding tracked issue.
- Do not commit secrets, credentials, or `.env` files.

### Dangerous operations — always confirm first

The following require explicit user confirmation before execution:

- `git push --force` or `git reset --hard`
- Deleting files, branches, or database tables
- Any operation affecting shared infrastructure or CI/CD pipelines
